# Product Lab 1.4

**От проблемы в метриках до обоснованного продуктового решения.**

Опубликованная версия: **https://site-pm-one.vercel.app** — собирается автоматически из ветки `main` (Vercel).

Интерактивный EdTech-прототип на русском языке: пользователь становится продакт-менеджером, расследует бизнес-проблему и принимает решение на основании данных. Для студентов, начинающих PM и аналитиков. Гипотеза продукта — последовательная практика помогает применять разрозненные знания; эффективность обучения пока не проверена исследованием.

История версий — в [CHANGELOG.md](CHANGELOG.md). Данные localStorage v2 сохраняются между версиями.

## Что работает без инфраструктуры

- **Девять сюжетных миссий:** MarketFlow, StreamBox, QuickFood, AdCraft, Formly, CloudNote, Discovery, SplitLab и итоговая Product City. Восемь открыты **в любом порядке**, итоговая — после трёх завершённых (ТЗ, п. 14).
- **Четыре этапа миссии:** диагностика по дереву метрик → гипотеза и метрики эксперимента → интерпретация A/B-теста → решение с обоснованием.
- **Диагностика:** дерево показывает формулы и знаки операций (×, ÷, +, −); после подтверждения сразу появляется разбор; за верную ветку на уровень выше — частичный балл.
- **Решение:** четыре варианта — внедрить для всех, ограниченный пилот, продолжить эксперимент, не внедрять (как в уроке C5). Причины выбираются из общего списка; верный набор вычисляется из статистики.
- **Честная оценка:** 100 баллов по пяти критериям, порядок вариантов перемешивается, к каждому неверному ответу есть пояснение «Почему не так». Подсказка на этапе стоит 2 балла и отмечается в разборе.
- **Разбор:** последствия решения, таблица «Что наблюдали / Что можем утверждать / Чего это не доказывает» (рассчитывается из данных варианта), ссылки на нужные уроки, сравнение попыток.
- **Вторая попытка с другими данными** — для пяти миссий с альтернативными наборами; у остальных вместо неё кнопка «Перейти к следующей миссии».
- **Теория — 14 уроков по документу доработок:** A — 4 (в т. ч. «Метрики тщеславия»), B — 5 (в т. ч. «Сильный диагноз»), C — 5 (в т. ч. «Какое решение принять после теста»). У каждого урока своя схема и мини-задание.
- **Статистика:** двусторонний z-тест разности долей, 95%-й интервал разности, интервалы Уилсона для групп, проверка SRM (χ²), проверка применимости нормального приближения.
- **Профиль навыков** по пяти критериям, XP без накрутки повторами, достижения, резервная копия прогресса файлом, игровой сертификат (PDF с кириллицей).
- **Лаборатория:** глоссарий со ссылками на уроки, формулы, A/B-калькулятор, дерево, воронка, удержание, юнит-экономика, источники.
- **Главная:** интерактивный пример, программа, блок «Три ловушки» со ссылками на миссии, FAQ, демо-тариф $100 000 (оплата не выполняется, ведёт на шуточную страницу).

## Страницы

`/` — главная; `/map` — карта миссий; `/cases` — каталог; `/mission/:id` — миссия; `/learn` — уроки; `/lab` — лаборатория; `/skills` — навыки и история; `/certificate` — сертификат; `/account` — профиль; `/methodology` — источники; `/privacy` — приватность.

Служебные страницы не показаны в меню, но открываются по прямому адресу: `/ranking` — рейтинг (заработает после подключения Supabase), `/admin` — админ-панель (то же). `/404` — шуточная страница демо-оплаты; любой другой неизвестный адрес показывает обычную 404.

## Архитектура

React 18, TypeScript, Vite, Tailwind CSS, Lucide, Recharts. Оболочка и маршруты — `App.tsx`; страницы — `pages/`; компоненты — `components/`; учебные инструменты — `features/`; предметная логика — `domain/` и `lib/`; данные миссий и уроков — `data/`.

- `src/lib/statistics.ts` — формулы z-теста, интервалов и SRM, форматирование чисел (запятая, минус).
- `src/lib/scoring.ts` — открытая детерминированная рубрика, вывод верного решения и причин из статистики, пояснения к ошибкам.
- `src/data/cases.ts` — миссии, варианты данных, подсказки, пояснения «почему не так»; таблица выводов строится функцией `buildTakeaways`.
- `src/data/lessons.ts` — 14 уроков со схемами.
- `src/styles.css` — базовые стили; `src/theme.css` — палитра, акценты и анимации поверх них.

## Supabase: подготовлено, но не подключено

Supabase в production **не настроен**: аккаунты, общий рейтинг и админ-панель не работают, прогресс хранится только в браузере. Инструкции — [docs/SUPABASE.md](docs/SUPABASE.md).

**Важно перед подключением:** серверная рубрика в SQL-миграциях написана для версии 1.3 (причины 0–5, три решения). В 1.4 добавлены причина № 6 и решение «Ограниченный пилот», изменено верное решение QuickFood. Перед включением серверной оценки нужна новая миграция с обновлённой рубрикой.

## Безопасность и приватность

Аналитика выключена до согласия; без backend события хранятся только локально. Заметка, почта, пароль и платёжные данные в события не попадают. Ключей в репозитории нет. Подробнее — `/privacy`.

- TypeScript и production-сборка проходят.
- **166 unit-тестов** (Vitest): статистика, согласованность деревьев всех вариантов, рубрика и причины, таблица выводов, пилот, глоссарий, порядок миссий, хранение прогресса.
- Сценарии Playwright обновлены под перемешанные варианты, свободный порядок и четыре решения; в этом релизе они **не запускались**.

## Материалы и ограничения

Доработки 1.4 сделаны по документу `Product-Lab-dorabotki.docx`: структура 14 уроков, подсказки первых трёх миссий, причины решения и таблица «Что можем утверждать» взяты из него. Тексты уроков — оригинальный пересказ.

Основной источник — Ian Sommerville, *Engineering Software Products*, Pearson, 2021 (разделы 1.1–1.2, главы 2–3); формулы статистики взяты не из него.

- https://iansommerville.com/engineering-software-products/
- https://docs.scipy.org/doc/scipy/reference/stats.html
- https://www.statsmodels.org/stable/stats.html
- https://www.itl.nist.gov/div898/handbook/

Компании и числа синтетические. Иллюстрация на главной создана нейросетью и подписана. Нет реальных платежей, аккредитации и доказанной учебной эффективности.

## Сценарий защиты на 3–5 минут

1. **0:00–0:45 — главная.** Аудитория и проблема, интерактивный пример, блок «Три ловушки».
2. **0:45–2:15 — миссия MarketFlow.** Дерево метрик со знаками операций → выбрать «Заказы», показать частичный балл и разбор сразу после подтверждения → гипотеза и метрики → A/B-тест: интервал через ноль, выборка 10 000 из 15 000 → решение «Продолжить эксперимент» с двумя причинами.

5. **4:15–5:00 — навыки, уроки, лаборатория.** Профиль пяти навыков, урок B2 «Сильный диагноз», источники. Честно: Supabase не подключён, эффективность обучения не исследована.
