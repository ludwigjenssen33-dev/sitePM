# Product Lab 2.0

**От проблемы в метриках до обоснованного продуктового решения.**

Интерактивный EdTech-прототип на русском языке: пользователь становится продакт-менеджером, расследует бизнес-проблему и принимает решение на основании данных. Для студентов, начинающих PM и аналитиков. Гипотеза продукта — последовательная практика помогает применять разрозненные знания; эффективность обучения пока не проверена исследованием.

## Что работает без инфраструктуры

- Светлый адаптивный лендинг, локальная AI-иллюстрация, интерактивный пример, программа, FAQ, честно обозначенные демонстрационные отзывы.
- Девять сюжетных миссий: исходные MarketFlow/StreamBox/QuickFood, рекламные расходы, неудачный интерфейс, цена подписки и отток, клики против прибыли, качество эксперимента и итоговый кейс.
- Четырнадцать уроков: A — 4, B — 5, C — 5. Схемы, интерактивные числа, мини-задания, ссылки из разбора.
- Математически проверенные деревья, вычисляемые A/B-тесты, интервалы Уилсона для групп, интервал разности, SRM и контрольные метрики.
- Четыре этапа, подсказки −2 балла, обоснование решения 12+8, последствия, разбор ограничений выводов и сравнение попыток.
- Альтернативные проверенные данные для трёх исходных и двух новых кейсов.
- История, XP без накрутки повторениями, достижения, карта обучения, профиль пяти навыков, локальный псевдоним.
- Явно обозначенный демонстрационный рейтинг; включение локального профиля только по согласию.
- Игровой сертификат при выполнении условий: просмотр, печать, настоящий PDF с кириллицей. Образец помечен отдельно.
- Девять разделов лаборатории: поиск по 15 терминам, формулы, A/B-калькулятор, дерево, кликабельная воронка, удержание, экономика/чувствительность, источники и методология.
- Product Lab Analytics: добровольные локальные события, отдельная синтетическая аналитика, метрики, когорты, графики и CSV.
- Демонстрационная админка с десятью разделами, редактором-песочницей, валидацией, версиями и журналом. Она не даёт серверных прав и не меняет рабочие миссии.
- Демо-тариф $100 000: подтверждение ведёт на фирменную 404, карты и списания отсутствуют.

## Запуск

Нужен Node.js **22.12+** (проверено на 24.19.0) и npm.

```bash
npm ci
npm run dev -- --port 5173
```

Откройте адрес, напечатанный Vite. Основной сценарий не требует ключей, backend или платных API. Для ограниченной облачной среды: `npm ci --cache /tmp/product-lab-npm-cache`. После переустановки зависимостей перезапустите Vite; при `Outdated Optimize Dep` добавьте `--force`.

```bash
npm run build
npm run preview -- --port 4173
npm test
```

Браузерные проверки:

```bash
npx playwright install chromium
npm run test:e2e
# Или с системным Chromium:
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

## Страницы

`/` — лендинг; `/map` — карта; `/cases` — каталог; `/mission/:id` — миссия; `/learn` — библиотека; `/skills` — навыки и история; `/ranking` — рейтинг; `/certificate` — сертификат; `/lab` — лаборатория; `/account` — аккаунт; `/admin` — административная демонстрация и проверка серверного доступа; `/methodology` — источники; `/privacy` — приватность; `/404` — демо-оплата/неизвестный адрес.

Старые ссылки `#case/market`, `#theory`, `#progress` поддерживаются. Vercel/Netlify настроены на возврат `index.html` при прямом открытии страниц.

## Архитектура

Сохранены React 18, TypeScript, Vite, Tailwind CSS, Lucide и Recharts. Монолитный App разделён: оболочка и маршрутизация в `App.tsx`, страницы в `pages/`, компоненты в `components/`, учебные инструменты в `features/`, предметная логика в `domain/` и `lib/`, события в `analytics/`, авторизация в `auth/`, адаптеры в `services/`. Тяжёлые страницы и PDF загружаются по запросу. PDF-модуль с поддержкой кириллицы заметно крупнее остальных и не входит в начальную загрузку.

`src/lib/statistics.ts` сохраняет корректные формулы z-теста и интервала разности. Вход валидируется; непригодное нормальное приближение не выдаёт p-value. `src/lib/scoring.ts` задаёт открытую детерминированную рубрику. Свободный текст не оценивается.

`product-lab-v1` не удаляется. Миграция в `product-lab-v2` сохраняет исторические баллы, ответы и лучший результат без пересчёта старой рубрики. Более свежие попытки защищены при слиянии, повреждённые записи сохраняются в recovery-копии.

## Supabase: что подготовлено и что ещё не подключено

В этой среде Supabase **не настроен**, миграция не применялась к живой БД. Поэтому гостевые баллы, рейтинг и сертификаты не заявляются как проверенные сервером.

Подготовлены настоящий Auth REST-адаптер (вход/регистрация/выход/восстановление), профиль, добровольный импорт архива прогресса, серверная проверка роли, SQL-схема, RLS, закрытые рубрики и RPC оценивания, подсказок, сертификатов, рейтинга и черновиков. Админка может проверять серверный доступ и читать ограниченные реальные данные после подключения.

Инструкции: **[docs/SUPABASE.md](docs/SUPABASE.md)**. Кратко:

1. Создайте Supabase-проект и примените `supabase/migrations/202610220001_platform.sql` через SQL Editor.
2. Настройте Site URL и разрешённые callback URL для Auth.
3. Скопируйте `.env.example` в `.env.local`; укажите `VITE_SUPABASE_URL` и только публичный anon/publishable key в `VITE_SUPABASE_ANON_KEY`.
4. Перезапустите Vite или пересоберите Preview.
5. После регистрации назначьте первого администратора из доверенного SQL Editor согласно инструкции. Самостоятельное назначение роли через клиент запрещено.

Для полного Connected Mode остаются публикация серверных версий контента/рубрик, привязка этапов миссий к RPC, серверные рейтинги/сертификаты в пользовательском интерфейсе и проверка миграции/RLS на реальном Supabase. Импорт локальных баллов не делает их доверенными. Service-role и любые секретные ключи на клиенте запрещены.

## Безопасность и приватность

Аналитика выключена до согласия. В гостевом режиме события сохраняются только локально; заметка, почта, пароль и платёжные реквизиты в события не попадают. При отказе локальные события удаляются. Статистика демо/локальная/серверная разделена.

Фото-иллюстрация и шрифт локальные; внешние ресурсы основного учебного процесса не нужны. Ключи в репозитории отсутствуют. Политика описана на `/privacy`. Не храните конфиденциальную информацию в учебной заметке. Приватный архив прогресса отправляется Supabase только после отдельного действия импорта.

Vitest обновлён после предыдущего аудита. Текущий `npm audit` сообщает **0 известных уязвимостей**; это не гарантия отсутствия всех возможных дефектов.

## Материалы и ограничения

**`Product-Lab-dorabotki.docx` отсутствует среди доступных вложений.** Структура изменений реализована по сообщению пользователя; точные тексты отсутствующего документа и предусмотренные в нём наборы данных не воспроизводились. Альтернативные сценарии и формулировки здесь авторские.

Основной источник — предоставленный PDF Ian Sommerville, *Engineering Software Products*, Global Edition, Pearson, 2021: разделы 1.1–1.2 и главы 2–3. Книга не является источником формул статистического тестирования. Учебные тексты оригинальные; компании и числа синтетические.

- https://iansommerville.com/engineering-software-products/
- https://docs.scipy.org/doc/scipy/reference/stats.html
- https://www.statsmodels.org/stable/stats.html
- https://www.itl.nist.gov/div898/handbook/

Новые отраслевые исследования не заявляются: доступ к дополнительным источникам ограничен прокси. Иллюстрация с женщиной создана AI и не выдаётся за фото реального студента. См. [происхождение изображений](docs/ASSETS.md); лицензия локального шрифта находится в `public/fonts/`.

Нет реальных платежей, официальной аккредитации, AI-преподавателя или доказанной учебной эффективности. Демонстрационная «публикация» редактора сохраняет версии только в песочнице, не изменяет рабочий каталог. Следующие шаги: подключение и интеграционные тесты Supabase, проверка доступности с пользователями, сопоставление с DOCX после его получения.

## Сценарий защиты на 3–5 минут

1. **0:00–0:45:** лендинг, аудитория и проблема. Покажите интерактивный пример, отметьте демонстрационные отзывы и тариф.
2. **0:45–2:15:** карта → MarketFlow. Дерево, гипотеза, метрики. Сравните A/B и план выборки; выберите продолжение и две подходящие причины.
3. **2:15–3:00:** последствия, 100 баллов, таблица границ выводов, ссылка на конкретный урок. Повторите с другими данными и покажите сравнение.
4. **3:00–4:00:** навыки, XP, рейтинг-демо, сертификат-образец/PDF. В лаборатории измените числа A/B или нажмите сегмент воронки.
5. **4:00–5:00:** админка-демо, источники и настройки аналитики. Честно объясните, что Supabase пока не подключён, а учебная эффективность не исследована.
