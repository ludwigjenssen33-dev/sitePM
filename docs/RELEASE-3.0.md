# Product Lab 3.0 — отчёт о доработке

Ветка: `feature/product-lab-3` (от `main` 8af00c4). В `main` изменения не вливались: объединение — только через pull request после проверки владельцем.
Точки возврата: теги `restore/01-original-1.3`, `restore/02-fixes`, `restore/03-design`, `restore/04-release-1.4`.

## Реализовано

- **Визуальный стиль.** Удалены декоративные знаки ✳, похожие на чужой логотип. Дизайн-система 3.0 на токенах (`src/theme.css`): белый фон, холодные серые поверхности, синий основной, бирюзовый вторичный, золотой для достижений, зелёный/янтарный/красный для статусов.
- **Навигация.** Главная, Курсы, Кейсы, Лаборатория, Рейтинг, Мой кабинет; «Админ-панель» — только при подтверждённой сервером роли. Мобильное меню ниже 1100 px. Читаемые адреса: `/courses/:курс/:урок`, `/cabinet/:раздел`. Старые адреса 1.x (`/learn`, `/skills`, `/certificate`, `/account`, `#theory`) ведут в новые разделы. В рабочей панели — быстрый возврат к следующему уроку.
- **Курсы.** 5 курсов, 39 уроков: «Основы продуктовой аналитики» — 10, «Продуктовые гипотезы» — 8, «A/B-тестирование» — 10, «Юнит-экономика» — 6 из 9 запланированных, «Продуктовый менеджмент на практике» — 5 из 10. Урок: проблема → инструмент → модель → интерактивный тренажёр → мини-практика с объяснением → применение в миссии → итог → литература. 10 типов тренажёров с проверкой ввода (п.п. и %, дерево метрик, воронка, удержание, A/B, размер выборки, LTV/CAC, ICE, сегменты, SRM). Поиск по урокам, хлебные крошки, список модулей, прогресс, «Назад» / «Завершить и продолжить».
- **Миссии.** Сохранены 9 прежних, добавлены 4 новые с согласованными данными: PayWise (финтех, вред по контрольной метрике безопасности), FitPulse (мобильное приложение, подглядывание до плановой границы), TaskHub (B2B SaaS, подтверждённый эффект), HomeStyle (e-commerce, двухуровневое дерево и незначимый результат). Для каждой тесты проверяют дерево метрик, совпадение решения с правилами рубрики и 100 баллов за обоснованные ответы.
- **Мой кабинет.** Обзор (текущий курс, следующая миссия, общий прогресс, XP, уровень, достижения, место в рейтинге, сильные и слабые навыки, рекомендованные уроки), «Мои курсы», «Навыки и история», «Сертификат», «Профиль и настройки» со сбросом прогресса через подтверждение.
- **Рейтинг.** Без сервера — явно помеченный демо-рейтинг: вымышленные участники с меткой «демо», ваш локальный результат, периоды «за всё время» / «за 7 дней», фильтр по курсу, топ-3, топ-100, ваше место, «Скрыть меня». Баллы — сумма лучших результатов по уникальным миссиям, повторы не накручивают сумму. С Supabase — серверный рейтинг без email.
- **Главная.** Стрелки остались только на настоящих ссылках: карточки преимуществ и программа ведут на курсы, карточка миссии кликабельна целиком. Убраны аватары-заглушки. Количество курсов, уроков и миссий берётся из данных.
- **Supabase.** Миграция `202610240001_product_lab_3.sql`: решения 0–3 (включая «Ограниченный пилот»), причины 0–6, частичный балл за соседнее решение, как на клиенте, порядок 13 миссий.

## Частично

- «Юнит-экономика» (6 из 9) и «Практика продакта» (5 из 10): в интерфейсе указано, сколько уроков готово из запланированных; шаблонных заглушек нет.
- У новых миссий один проверенный набор данных: повтор идёт на тех же данных, а не на альтернативном варианте.
- Сертификат, админ-панель, импорт локального прогресса и аналитика событий перенесены из 1.4 без переработки; добавлены события `course_viewed` и `lesson_started` для страниц курсов.

## Не реализовано

- Реальное подключение Supabase: проекта и ключей нет, поэтому вход, подтверждение почты, сброс пароля, серверный рейтинг и админ-панель в рабочем режиме не проверялись. Администратор **не создан**.
- Всплывающие подсказки к терминам, индикатор несохранённых изменений, drill-down воронок, когорты и CSV в админ-панели в 3.0 не дорабатывались.
- Playwright e2e не запускались.

## Как безопасно назначить первого администратора

Порядок описан в `docs/SUPABASE.md`: зарегистрироваться обычным способом, затем владелец проекта в SQL Editor Supabase назначает роль по UUID пользователя. Пароли в репозиторий, миграции и документацию не записываются, клиент не может выдать себе роль.

## Проверки

- `vitest run`: 18 файлов, 200 тестов — пройдены.
- `tsc -b` и `vite build` — успешно (предупреждение о размере PDF-чанка; он загружается только при скачивании сертификата).
- В браузере: 19 маршрутов на ширинах 320, 375, 768, 1024 и 1440 px — без горизонтальной прокрутки и пустых страниц; прохождение урока сохраняет прогресс и ведёт к следующему уроку.
- SQL-миграция проверена только структурными тестами; в PostgreSQL не выполнялась.

Все компании, люди и числа в уроках и миссиях вымышлены и служат учебными примерами.
