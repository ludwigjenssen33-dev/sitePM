# Закрытая админка Product Lab 4.0

Supabase в текущей версии **не используется**. Нет обычной регистрации: обучение и прогресс остаются локальными. Исторические файлы Supabase сохранены для истории, но не входят в пользовательский runtime.

## Первоначальная локальная настройка

```bash
npm ci
npm run admin:setup
npm run dev -- --port 5173
```

Команда криптографически генерирует уникальный логин и 48-символьный пароль. Не выводит их в консоль. Не перезаписывает существующие настройки. Создаёт только игнорируемые Git файлы:

- `.private/admin-credentials.json` — данные входа, права 0600, каталог 0700. Открывайте приватно. После сохранения в менеджере паролей файл можно удалить.
- `.env.local` — логин, scrypt-хеш (N=32768, r=8, p=1, соль 24 байта, ключ 64 байта) и случайный серверный секрет. Пароля в серверном env нет.
- `.private/vercel-admin.env` — точные значения серверных переменных для переноса в интерфейс Vercel. Также 0600. Не публиковать, не добавлять в репозиторий, не использовать как VITE-переменные.

Открыть `/admin/login`; панель — `/admin/dashboard`. Локально без БД сессии и лимиты живут в памяти процесса; панель подписана **«Демонстрационный режим · БД не подключена»**. Это не сбор общей статистики. Перезапуск dev-сервера отзывает локальные сессии. В production вход без БД намеренно закрыт: распределённый лимит попыток нельзя надёжно хранить в памяти Vercel Function.

## Vercel и постоянное хранилище

Нужна существующая PostgreSQL 14+ с TLS и серверным подключением. Подойдёт доступный владельцу бесплатный тариф или собственная БД. Проект не создаёт внешние аккаунты и не подключает платные услуги.

1. В SQL-консоли владельца БД выполнить `database/001_analytics.sql`. Миграция повторяема. Выделить серверную роль с DML-доступом только к `pl_events`, `pl_admin_sessions`, `pl_rate_limits`, без публичного SQL/API доступа. Не выдавать ей права владельца схемы.
2. Vercel → Project → Settings → Environment Variables. Добавить **серверные** `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, `ADMIN_SESSION_SECRET` из `.private/vercel-admin.env`. Вставлять значения непосредственно в поля, без dotenv-экранирования или внешних кавычек. `ADMIN_PASSWORD_HASH` содержит буквальные `$`, это нормально.
3. Добавить `DATABASE_URL` (либо `POSTGRES_URL`) из провайдера. Нужен URL пула, рассчитанный на serverless. TLS и проверка сертификата определяются URL провайдера; `rejectUnauthorized:false` проект не использует.
4. Необязательно задать `APP_ORIGIN=https://ваш-домен`. Значение должно совпадать с Origin браузера. Для Preview назначать отдельный домен/окружение либо оставить переменную пустой: по умолчанию сверяется Host текущего запроса. Используйте отдельную тестовую БД для Preview, чтобы не смешивать события production и проверки.
5. Создать Preview Deployment из ветки. Node.js 22+, `npm run build`, output `dist`. `api/[...path].ts` — отдельная Node Function; SPA rewrite исключает `/api/`.
6. Проверить реальный вход/выход. После согласия в другом браузере пройти урок, обновить панель: режим должен быть **«Серверные события · PostgreSQL»**, данные — из БД. Пустая БД показывает пустое состояние, синтетический набор в реальном режиме не подставляется.

Никогда не устанавливать секреты с префиксом `VITE_`. Не передавать пароли в аргументах CLI, коммитах, PR, документации или скриншотах.

## Защита

- Сервер проверяет пароль, используя scrypt и сравнение постоянного времени. Единственный аккаунт определяется серверным env. Нет клиентского «админа», демо-пароля или процедуры назначения роли из браузера.
- Сессионный токен: 32 случайных байта. БД хранит только SHA-256 токена, срок 8 часов. Cookie `__Host-productlab_admin`: HttpOnly, Secure, SameSite=Strict, Path=/, без Domain. Выход удаляет серверную запись, повтор старого cookie не работает.
- Каждый административный API проверяет сессию. POST требуют совпадение Origin, JSON и специальный заголовок; CORS-доступ не предоставляется.
- 5 попыток входа / 15 минут на HMAC адреса и 30 / 15 минут суммарно на аккаунт. Лимит хранится атомарно в PostgreSQL, одинаковые сообщения для неправильного логина и пароля. Временный HMAC адреса не попадает в учебные события.
- Приём событий: до 20 событий, 48 КБ, 240 запросов в минуту на HMAC адреса; белый список полей и типов, UUID, окно 7 дней, отсечение будущего времени, idempotency по ID. Пароли, тексты ответов и заметки не принимаются в параметрах.
- Серверные ошибки не выводят SQL, URL БД или секреты. React не использует опасную вставку HTML для контента.

## Обслуживание

Раз в сутки выполнить три DELETE-команды, приведённые в конце миграции: события старше 90 дней, просроченные сессии, старые лимиты. Настроить это в имеющемся планировщике БД; платные Vercel Cron не требуются. Политика 90 дней зависит от выполнения владельцем этой процедуры.

Для отзыва всех сессий: `DELETE FROM pl_admin_sessions;`. Для смены пароля сгенерировать новый набор в отдельной локальной папке, приватно заменить env в Vercel, удалить сессии, выполнить redeploy. `admin:setup` специально не перезаписывает действующие настройки. При компрометации также заменить ADMIN_SESSION_SECRET и доступ БД.

## Ограничения аналитики

Это добровольные клиентские события. Анонимный ID означает браузер, а не подтверждённого человека; очистка данных, блокировщики и разные устройства влияют на подсчёт. Баллы и выдача игровых сертификатов поступают от клиента, не являются серверной аттестацией. Локальные заметки и полный прогресс не синхронизируются. Отзыв согласия удаляет локальную очередь и ID, но не уже переданные события. В интерфейсе период UTC; максимум 20 000 событий за отчёт с явным предупреждением об усечении. Воронки считают порядок, уникальность и окно перехода, а не независимые суммы кликов.
