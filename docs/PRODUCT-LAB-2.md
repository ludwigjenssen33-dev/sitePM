# Product Lab 2.0 — руководство по прототипу

> **Исторический документ версии 1.2–1.3.** Актуальное описание, порядок миссий, структура уроков и сценарий защиты — в [README.md](../README.md) (версия 1.4).

Product Lab — интерактивная образовательная платформа для студентов, начинающих продакт-менеджеров и аналитиков. Учебная гипотеза продукта: последовательная практика диагностики, формулирования гипотез и интерпретации экспериментов помогает связать разрозненные знания с принятием решений. Учебная эффективность пока не подтверждена исследованием с пользователями.

GitHub → Vercel может автоматически создать Preview для этой ветки; факт доступности Preview нужно проверять по результату платформы, а не выводить из успешной сборки.

**`Product-Lab-dorabotki.docx` в рабочей среде не найден.** Поэтому точные тексты подсказок, шести причин, таблиц и альтернативных сценариев из этого документа не воспроизводились и не считаются проверенными. Использованы требования из сообщения пользователя; формулировки учебных материалов оригинальные. Перед финальным сопоставлением со спецификацией документ следует предоставить отдельно.

## Архитектура

Основа сохранена: React 18, TypeScript, Vite, Tailwind CSS, Lucide и Recharts. Предметные расчёты отделены от представления:

- `src/data/` — версии учебных кейсов, варианты данных, 14 слайдов и ссылки между материалами.
- `src/lib/` — статистика, математическая проверка деревьев, открытая детерминированная рубрика; сохранён совместимый загрузчик старого прогресса.
- `src/domain/progress.ts` — попытки, лучшие результаты, навыки, уровни, XP, достижения, рейтинги и условия сертификатов.
- `src/services/progressStore.ts` — локальная схема v2 и миграция прогресса v1.
- `src/services/supabase.ts`, `src/auth/` — граница подключения к Supabase Auth и PostgreSQL, проверка серверной роли.
- `src/analytics/` — события с ограниченной схемой, согласие, метрики и упорядоченные воронки; демо-данные отделены от локальных событий.
- `src/components/` — повторно используемые компоненты, включая кликабельную воронку.
- `src/pages/`, `src/features/` — разделы платформы и интерактивные инструменты лаборатории.
- `supabase/migrations/` — структура базы, ограничения и RLS. Развёртывание этих миграций выполняется отдельно.
- `public/images/` — локально оптимизированные иллюстрации; приложение не зависит от внешнего фотосервиса.

## Локальный запуск и проверки

Требуется Node.js 22+ и npm. Рабочая директория — `/workspace/sitePM`.

```bash
npm ci
npm run dev -- --port 5173
```

В ограниченной облачной среде можно перенести npm cache: `npm ci --cache /tmp/product-lab-npm-cache`. После переустановки зависимостей перезапустите уже работающий Vite. При `Outdated Optimize Dep` используйте `npm run dev -- --port 5173 --force`.

## Учебный процесс

Пользователь играет роль PM в вымышленной компании. Сообщение виртуального руководителя задаёт бизнес-контекст. Далее следуют диагностика дерева, гипотеза и метрики, интерпретация эксперимента, решение с выбором причин. Последствия решения — детерминированный учебный сценарий, а не реальные наблюдения бизнеса.

Рубрика открыта: диагностика — 25, гипотеза — 20, метрики — 15, интерпретация — 20, решение — 20 (12 за выбор + 8 за причины). Использование подсказки на этапе стоит 2 балла и фиксируется в попытке. Подсказка помогает рассуждать, а не выдаёт готовый ответ. Текстовое поле рефлексии не должно оцениваться совпадением ключевых слов.

Повторные попытки сохраняются отдельно. Лучшие результаты по уникальным кейсам используются для профиля навыков и рейтинга; повторение одной миссии не должно бесконечно увеличивать XP. При варианте с другими данными математические связи и статистический вывод пересчитываются. Пользователю не показываются технические идентификаторы вариантов.

## Статистика и границы выводов

Основной метод — двусторонний z-тест независимых долей с объединённой вероятностью под H₀. 95%-й интервал эффекта — нормальное приближение с непуленной стандартной ошибкой. Нормальное приближение нельзя использовать при слишком малом числе успехов или неуспехов. Для визуализации долей групп допустимы отдельные интервалы Уилсона.

- p-value не является вероятностью истинности гипотезы.
- Положительный uplift не гарантирует коммерческий успех.
- Незначимость не доказывает отсутствие эффекта.
- Продолжение допустимо по заранее зафиксированному плану, а не до удобного p-value.
- SRM и ошибки рандомизации требуют расследования, даже если эффект выглядит убедительным.
- По одной агрегированной конверсии нельзя автоматически утверждать значимость денежного эффекта.

Все компании и показатели кейсов синтетические. Внешние источники обосновывают метод и характер проблемы, но не выдаются за исследования именно этих вымышленных компаний.

## Demo и Connected

**Demo:** гостевой пользователь, локальный прогресс, явно помеченные синтетические рейтинги и аналитика, пример сертификата, просмотр демонстрационной админ-панели. Демо-доступ не является настоящей ролью администратора. Демонстрационный редактор контента не должен изменять результаты пользователей.

**Connected:** требует реального Supabase-проекта, применения SQL-миграций и переменных окружения. Отсутствие этих настроек — не успешная авторизация и не подключённая база. Инструкции и безопасное назначение первого администратора находятся в `docs/SUPABASE.md`. Публичный Supabase anon/publishable key допустим на клиенте при корректной RLS; service-role key на клиенте недопустим.

При первом входе локальный прогресс импортируется только после согласия пользователя. Более старые локальные записи не должны заменять более новые серверные данные. Серверные баллы, роли и сертификаты нельзя считать доверенными только потому, что их отправил браузер.

## Аналитика и приватность

Сбор событий должен быть явным и минимальным: тип события, версия, время, допустимый идентификатор сессии/пользователя и ограниченный набор параметров. Пароли, реквизиты карт, свободное текстовое обоснование и электронная почта не относятся к параметрам учебной аналитики.

Демонстрационная аналитика не смешивается с локальной реальной активностью. Для отсутствующих или недостаточных данных показывается соответствующее состояние, а не выдуманный DAU или retention. Воронка учитывает порядок событий, временное окно и уникальные идентификаторы; повторные клики не равны новым пользователям.

Данные localStorage доступны другим скриптам того же origin и не шифруются. В браузерном прогрессе не следует хранить секреты. Согласие на локальную аналитику не означает автоматического согласия на внешний сбор.

## Демонстрационная оплата и сертификат

Цена Premium — **100 000 долларов США**, намеренная учебная гипербола. Никаких настоящих операций и ввода карты. Демонстрационный провайдер оплаты ведёт на фирменную 404 с возможностью вернуться к обучению.

Сертификат — игровой документ, не документ об образовании и не признанная профессиональная квалификация. Локальная выдача действует только внутри демонстрационного режима. Серверная выдача должна проверять завершение обязательных миссий, итоговый кейс и средний балл, а не принимать произвольный запрос клиента.

## Публикация без изменения production

Для Vercel: используйте ветку `feature/product-lab-2`, Vite, команду `npm run build`, каталог `dist`. В существующем проекте Vercel следует использовать Preview Deployment для ветки; production branch остаётся `main`. При отсутствии доступа к Vercel можно предоставить PR и сравнение веток, не придумывая адрес Preview.

Для Netlify: существующий `netlify.toml` задаёт сборку и `dist`. При использовании путей вместо hash-навигации нужны правила SPA fallback. Проверяйте прямое открытие `/admin`, страницы лаборатории и 404 после публикации.

## Сценарий демонстрации — 5 минут

1. **0:00–0:40:** новый лендинг, карта миссий, честная демонстрационная цена.
2. **0:40–2:10:** миссия MarketFlow: сообщение руководителя, дерево, диагноз, выбор гипотезы и метрик.
3. **2:10–3:10:** доверительные интервалы, блок доверия к тесту, решение с причинами и последствия.
4. **3:10–3:50:** результат, штраф за подсказки, сравнение попыток, профиль навыков и конечный XP.
5. **3:50–4:30:** интерактивная воронка: нажать сегмент, сменить устройство/период, экспортировать CSV.
6. **4:30–5:00:** лаборатория, игровой сертификат, демо-админка и честное сообщение о неподключённом Supabase.
