# Product Lab 1.3 — итог

## Выполнено

- Последовательная игровая дорожка с аватаром на текущем шаге, главами, замками и финишем.
- Открытие следующей миссии после завершения предыдущей; защита прямых ссылок. Ранее начатые/завершённые задания сохраняют доступ. Свободный каталог доступен только после подтверждённой сервером роли администратора.
- Карточка продолжения незавершённого обучения, серия дней без штрафа за перерыв, прямой переход к следующей миссии после результата.
- Обмен результатом: системное меню, ссылка на отдельную страницу и PNG. В экспорт не попадают имя, заметки, ответы или история. Локальный балл помечен как не проверенный сервером.
- Резервная копия прогресса, импорт с объединением и сохранением более свежих попыток; локальный псевдоним для игрового сертификата.
- Плавные переходы и поддержка reduced motion; принудительное приветственное окно убрано.
- Демонстрационные пользователи/метрики больше не показываются через административный раздел или общий рейтинг. Без сервера — честное отсутствие данных.
- Подготовлена доставка добровольных реальных событий гостей и аккаунтов в Supabase, серверная валидация, дедупликация, сегменты и повторная доставка. Роли меняются через защищённый журналируемый RPC; порядок миссий проверяется также серверным start_attempt.
- Безопасная команда admin:create создаёт случайный логин/пароль только через настоящий Admin API. Сервисный ключ не входит в frontend, пароль сохраняется в игнорируемый приватный файл, не печатается в журнал.
- Версии 1.1, 1.2, 1.3 сохранены в CHANGELOG.md и src/data/releases.ts. Схема хранения v2 не переименована и не очищена.

## Внешний блокер — честный статус

Supabase URL/ключи и доступ к настройкам Vercel в среде отсутствуют. Поэтому реальный аккаунт администратора **не создан**, логина/пароля для работающего входа пока нет. Общие посещения пользователей не начали поступать в БД; задним числом их восстановить нельзя. Синтетические данные не выдаются за реальные метрики.

Для завершения этой части нужны действующий Supabase-проект, обе миграции, публичные переменные в Vercel и запуск `npm run admin:create` доверенным оператором с серверным ключом. Пошагово: ADMIN-1.3.md. Ключи не следует присылать в чат. Сервисный ключ не нужно помещать в VITE_*.

Новая миграция пока не выполнялась в PostgreSQL. Серверный рейтинг требует также проверенных серверных попыток; локальные оценки не становятся доверенными при импорте.

## Проверки

- TypeScript и production-сборка — успешно.
- 155 Vitest-тестов — успешно.
- 3 отдельных Node-теста создания администратора на mock: отказ без конфигурации, создание/роль/сохранение и откат — успешно.
- 26 браузерных сценариев проверены: 25 прошли общим прогоном; один тест воронки повторно прошёл после исправления локатора роли tab. Продуктовая ошибка в воронке не обнаружена.
- Проверены все девять миссий, причины/подсказки, старая миграция, ограничения порядка, невозможность роли через localStorage, обмен ссылкой и сигнатура PNG, резервная копия и ошибочный импорт, 320 px без переполнения.
- npm audit — 0 известных уязвимостей.
- Фото и цифры учебных компаний остаются учебными иллюстрациями. Реальной учебной эффективности и улучшения retention не заявляется: эти гипотезы ещё предстоит измерить.

## Публикация

Изменения подготовлены для main по прямой просьбе владельца. Git push запускает подключённую автоматическую сборку Vercel, но успешный push не доказывает завершение deployment. Подтверждённой ссылки или статуса Vercel в этой среде нет.
